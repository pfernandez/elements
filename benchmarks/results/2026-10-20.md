# Local keyed table comparison — 2026-10-20

The reconciliation changes reduce distant-swap time substantially and improve
partial updates. Creation and full replacement are approximately unchanged.
This is a small local comparison, not an official benchmark submission or a
general performance ranking. [Raw samples and metadata](./2026-10-20.json) and
[reproduction instructions](../README.md) accompany these results.

Median total interaction time in milliseconds, including browser rendering:

| Workload | Elements before | Elements after | React Hooks | Vanilla JS |
| --- | ---: | ---: | ---: | ---: |
| Create 1,000 rows | 53.6 | 55.0 | 43.9 | 37.5 |
| Replace 1,000 rows | 62.3 | 61.8 | 54.5 | 41.9 |
| Update every tenth row | 37.4 | 31.8 | 27.2 | 20.4 |
| Select a row | 11.2 | 10.4 | 9.8 | 5.1 |
| Swap two distant rows | 167.3 | 31.5 | 168.4 | 24.0 |
| Remove a row | 22.1 | 21.9 | 21.0 | 20.7 |
| Create 10,000 rows | 546.6 | 542.9 | 598.8 | 401.2 |
| Append 1,000 rows | 62.2 | 59.8 | 56.0 | 42.1 |
| Clear 1,000 rows | 34.6 | 30.3 | 29.7 | 15.6 |

The partial update's scripting median fell from 16.1 to 12.1 ms; the swap's
scripting median fell from 23.3 to 6.1 ms. These are separate medians, so scripting
and painting medians do not necessarily sum to the total median. A browser
regression test verifies that the distant swap now moves two rows instead of
997, while preserving a focused control in the middle. A rotation moves one
row; appends and removals do not move retained rows.

Environment: Intel Core i7-1270P, Linux x86_64, Chrome 155.0.8059.84 headless,
Node 25.9.0. Harness commit: `3ab4ceaf5591771228f83fb5161b9fda7e15934d`.
Elements baseline: `2e494da`; after: the reconciliation changes in this report.
React: 19.2.0, upstream production React Hooks adapter with memoized rows.
Elements retains unchanged row vnodes using the same item-reference and
selection comparison. All implementations passed the keyed identity checks.

There are five samples per operation, fifteen for selection, using upstream
warmups and retaining every sample. The harness applies 4× CPU slowdown to
partial update, selection, swap and clear; 2× to removal; none to the others.
Frameworks ran sequentially: Elements after, Elements before, React Hooks,
then vanilla, without concurrent project builds or tests. Order was not randomized and system noise
was not controlled. Repeat with more samples before making release claims.

The complete Elements table bundle grew from 6221 to 6503 gzip bytes.
This includes the benchmark application; it is not a package-size measurement.
Memory, startup, fresh construction of every row, and shared-observer fan-out
are outside this comparison. Further work on observer notification, history
snapshots and tick scheduling remains separate from these matching and placement
optimizations.
